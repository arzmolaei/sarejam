# موتور خواندن پیامک (`engine/parser`)

✅ ساخته شده و تست‌شده (۲۵ تست: ۵ بانک با نمونه واقعی + ۱۰ قالب رایج بدون نمونه). Kotlin خالص؛ `gradle :engine:parser:test`.

## مراحل

1. شناسایی بانک: فرستنده (`BankProfiles.bySender`) یا سرخط متن (`byBody`).
2. نرمال‌سازی: رقم فارسی/عربی → انگلیسی، «ي/ك» → «ی/ک»، حذف علامت‌های جهت، `٬` → `,`.
3. فرستنده موبایل شخصی (`09…`) و بی‌ربط → `NotBank` (هرگز ذخیره نمی‌شود).
4. رمز یک‌بارمصرف → `Otp` با فقط مبلغ و کارت مقصد؛ خود رمز خوانده نمی‌شود.
5. ورود / تبریک / اطلاعیه → `Ignored`.
6. مبلغ و جهت (به ترتیب): «مبلغ:» با علامت ← «برداشت/واریز» چسبیده به عدد ← خط تنهای `+`/`-` ← «… ریال».
7. مانده، حساب، کارت مقصد، تاریخ (کامل، سال دورقمی، یا ماه/روز با سال از زمان دریافت)، خط توضیح، اطمینان.
8. چیزی که بانکی است ولی خوانده نشد → `NeedsReview` (هیچ‌وقت دور ریخته نمی‌شود).
9. فرستنده ناشناس فقط وقتی تراکنش است که مانده هم داشته باشد.

## بانک‌های با نمونه واقعی

| بانک | فرستنده | جهت | شکل تاریخ | نکته |
| --- | --- | --- | --- | --- |
| پارسیان | `PARSIANBANK` | `+`/`-` کنار «مبلغ:» | `08/12` + `12:41` | پیامک رمز «انتقال به … مبلغ … رمز» جدا |
| بلو | `+9890000258` | «برداشت پول» | `۱۴۰۵.۰۷.۰۱` | بدون شماره حساب، گاهی بدون فاصله قبل «ریال» |
| ملت | `Bank Mellat` | «برداشت»/«واریز» چسبیده | `05/08/08-10:28` | بدون فاصله |
| رسالت | `ResalatBank` | خط تنهای `+`/`-` | `08/07_23:05` | کارمزد پیامک جدا؛ خط توضیح |
| شهر | `Bank Shahr` | «برداشت از» | `1405/06/22 18:58:06` | حروف عربی، سرخط با ستاره، پیامک تبریک |

سایر بانک‌ها با قواعد عمومی خوانده می‌شوند و BIN کارتشان در `BankProfiles` هست. فرستنده‌های بانک‌های بدون نمونه حدسی‌اند و باید با نمونه واقعی تأیید شوند.

## بانک‌های بدون نمونه: قالب‌هایی که از قبل پوشش داده شده‌اند

ممکن است نمونه بانک دیگری هرگز نرسد؛ پس قواعد عمومی برای همه قالب‌های رایج ساخته و تست شده‌اند (`GenericLayoutsTest`، نمونه‌های ساختگی):

| حالت | مثال | نتیجه |
| --- | --- | --- |
| کلمه + دونقطه | `برداشت:1,250,000` | برداشت |
| علامت بعد از عدد (چیدمان راست‌به‌چپ) | `1,500,000-` | برداشت |
| اصطلاح حسابداری | `بستانکار: 7,000,000` / `بدهکار: 200,000` | واریز / برداشت |
| خرید کارتی با حروف عربی | `خريد كارتي … مبلغ: 450,000 ريال` | برداشت |
| پیامک انگلیسی | `Withdrawal: 2,000,000` · `Balance:` | برداشت |
| مبلغ به تومان | `150,000 تومان` | ×۱۰ → ۱٬۵۰۰٬۰۰۰ ریال |
| برگشت وجه | `عودت وجه خرید` | واریز + `kindHint = refund` |
| تراکنش ناموفق | `خرید ناموفق` | `kindHint = failed` (خرج حساب نمی‌شود) |
| همه رقم‌ها فارسی | `واریز:۲٬۵۰۰٬۰۰۰` | واریز |
| مانده منفی (اعتباری) | `مانده: -200,000` | مانده منفی |

هر چیزی که باز هم خوانده نشود به صف بررسی می‌رود و کاربر با لمس مبلغ و مانده الگو را یاد می‌دهد (ROADMAP 1.7)؛ آن الگو فقط روی همان گوشی ساخته می‌شود و به نمونه واقعی از کاربر نیازی ندارد.

## ربط‌دهنده‌ها (`Linker`)

| تابع | چه پیدا می‌کند | مثال واقعی |
| --- | --- | --- |
| `linkOtps` | رمز + برداشت بعدی ظرف ۵ دقیقه → کارت مقصد و کارمزد | شهر: ۱٬۸۰۰٬۰۰۰ → برداشت ۱٬۸۱۱٬۰۰۰ (کارمزد ۱۱٬۰۰۰) |
| `findFees` | برداشت کوچک ظرف ۲ دقیقه کنار برداشت بزرگ همان حساب | رسالت: ۱۴٬۵۰۰ کنار ۱۵٬۰۰۰٬۰۰۰ |
| `findInternalTransfers` | برداشت از یک حساب خودم + واریز به حساب دیگر خودم | — |
| `findPassThrough` | واریز و برداشت تقریباً برابر از همان حساب → «فقط رد شد؟» | ملت: ۵٬۰۰۰٬۰۰۰ آمد، ۵٬۰۱۱٬۰۰۰ رفت |

حدها محافظه‌کارانه‌اند: ربط پیدا نشده فقط یک سؤال بیشتر است، ربط غلط گزارش را خراب می‌کند.

## اضافه کردن بانک یا قالب جدید

1. نمونه را ناشناس کن (اسم، شماره حساب/کارت، رمز، IP عوض؛ مبلغ و قالب بماند) و در `Fixtures.kt` بگذار.
2. تست بنویس که قرمز شود.
3. اگر فقط فرستنده جدید است → `BankProfiles`؛ اگر قالب جدید است → قاعده در `SmsParser`.
4. همه تست‌ها سبز.

## کارهای بعدی موتور (در ROADMAP)

- انتقال `BankProfiles` به `banks.json` قابل آپدیت.
- یاد گرفتن الگو از کاربر (لمس مبلغ و مانده روی پیامک ناشناخته).
- تشخیص افت ناگهانی درصد خواندن یک بانک.
- تجزیه نوتیفیکیشن اپ‌ها (بلو، اسنپ‌پی، دیجی‌پی، همراه‌بانک‌ها) با همان خروجی.
