# معماری سرجمع

همه‌چیز روی گوشی است (هیچ داده‌ای بدون انتخاب صریح کاربر بیرون نمی‌رود) و داده از بالا به پایین حرکت می‌کند: ورودی‌ها → موتورها → دیتابیس رمزدار → رابط.

```
ورودی‌ها   پیامک بانک | نوتیفیکیشن اپ‌ها | ثبت دستی/صوتی | عکس رسید
    ↓
موتورها    engine:parser (تجزیه) → engine:insight (دسته‌بندی، ربط‌دهی، کنترل مانده)
    ↓
داده       core:database (Room + SQLCipher)  ←→  data:backup (بکاپ رمزدار)
    ↓
رابط       feature:today | finance | work | life | settings | onboarding
```

## ماژول‌ها

| ماژول | کار | وابسته به |
| --- | --- | --- |
| `app` | Application، ناوبری، Hilt، تم | همه feature‌ها |
| `core:model` | مدل‌های دامنه (Kotlin خالص) | — |
| `core:common` | تاریخ شمسی، قالب مبلغ (عدد و حروف)، Result، dispatcherها | model |
| `core:database` | Entity، DAO، Migration، رمزنگاری | model |
| `core:ui` | سیستم طراحی Compose: رنگ، تایپوگرافی، تم‌ها، اجزای مشترک | common |
| `engine:parser` ✅ | تجزیه پیامک/نوتیفیکیشن (Kotlin خالص، بدون اندروید) | — |
| `engine:insight` | قانون‌های دسته‌بندی، ربط‌دهنده‌ها، پیش‌بینی، خرج تکراری (Kotlin خالص) | model, parser |
| `capture` | `SmsReceiver`، `BankNotificationListener`، اسکن صندوق، WorkManager | parser, insight, database |
| `data:backup` | بکاپ/بازگردانی رمزدار، CSV/Excel | database |
| `feature:*` | صفحه‌ها (ViewModel + Compose) | ui, database, insight |

قانون وابستگی: `feature` به `feature` دیگر وابسته نیست؛ `engine:*` به اندروید وابسته نیست (تست JVM سریع).

## فناوری‌ها

Kotlin، Jetpack Compose + Material 3، Hilt، Room + SQLCipher (کلید در Android Keystore)، Coroutines/Flow، WorkManager، DataStore، Glance (ویجت)، androidx.biometric، ML Kit Text Recognition روی گوشی (نسخه ۴). minSdk 26.

## جریان یک پیامک

1. `SmsReceiver` (ثبت‌شده در Manifest برای `SMS_RECEIVED`) متن و فرستنده را می‌گیرد.
2. `SmsParser.parse` → `NotBank` (هیچ ذخیره‌ای) · `Otp` (فقط مبلغ و کارت در جدول موقت ۱۰ دقیقه‌ای) · `Ignored` · `NeedsReview` · `Transaction`.
3. تراکنش: ساخت **Source** (اثر انگشت ورودی) ← پیدا/ساخت حساب ← حذف تکراری با اثر انگشت ← ربط‌دهنده‌ها ← کنترل مانده ← دسته‌بندی.
4. هر نتیجه خودکار (دسته، ربط، ادغام) یکی از سه وضعیت را دارد: **قطعی** (خودکار، با Undo) · **پیشنهاد** (در صندوق اصلاحات) · **نامشخص** (سؤال). فقط قطعی بی‌سؤال اعمال می‌شود و همیشه دلیلش ذخیره می‌شود («چرا؟»).
5. کار سنگین (اسکن صندوق) فقط با `WorkManager`، نه داخل گیرنده.

نوتیفیکیشن اپ‌ها: `NotificationListenerService` فقط برای بسته‌های فهرست سفید (اپ‌های بانکی و پرداخت) متن را به همان موتور می‌دهد؛ بقیه فوراً رد می‌شوند.

## مدل داده

| جدول | بخش | فیلدهای مهم |
| --- | --- | --- |
| Account | مالی | نوع (بانک، نقد، کیف الکترونیکی، اعتباری، سپرده)، بانک، اسم، ۴ رقم آخر، فضا (شخصی/کاری)، ارز، مانده آخر، بایگانی |
| Transaction | مالی | حساب، مبلغ (Long ریال)، جهت، زمان، مانده بعد، **نوع** (`EXPENSE` · `INCOME` · `TRANSFER` · `FEE` · `REFUND` · `REVERSAL` · `ADJUSTMENT` · `FAILED`)، دسته، طرف حساب، وضعیت (در انتظار/تأییدشده)، گروه انتقال، کارمزدِ (id)، برگشتِ (id)، `sourceIds`، `parserVersion`، `userEditedFields` (فیلدهایی که کاربر دستی عوض کرده و هرگز بازنویسی نمی‌شوند)، دلیل تشخیص و اطمینان |

| Split | مالی | تراکنش، دسته، مبلغ |
| Category | مالی | اسم، آیکون، رنگ، والد (دو سطح) |

| Counterparty | مالی | اسم، کارت/شبا، دسته پیش‌فرض، «مال خودم» |
| Rule | مالی | شرط‌ها، دسته نتیجه، درست/غلط، اطمینان |

| Debt | مالی | شخص، مبلغ، جهت، سررسید، بازپرداخت‌ها |
| Asset | مالی | نوع (طلا، ارز، سهام)، مقدار، قیمت آخر |
| Project / Task | کاری | عنوان، سررسید، تکرار، اولویت، شرط تیک خودکار با تراکنش |
| Habit / HabitLog | شخصی | برنامه، روزهای انجام‌شده |
| Goal | شخصی/مالی | مقدار هدف، موعد، پیشرفت |
| Note | شخصی | متن، تاریخ، برچسب |

همه جدول‌ها `createdAt` و `updatedAt` دارند (برای همگام‌سازی آینده). نگه داشتن RawMessage اجازه می‌دهد بعد از بهتر شدن الگوها، پیامک‌های قدیمی دوباره خوانده و اصلاح شوند؛ تجزیه دوباره فقط فیلدهای خارج از `userEditedFields` را عوض می‌کند و تغییرش را با Undo نشان می‌دهد.

**گزارش‌ها:** خرج = فقط `EXPENSE` + `FEE` منهای `REFUND`/`REVERSAL` مرتبط؛ `TRANSFER`، `ADJUSTMENT` و `FAILED` هرگز خرج یا درآمد حساب نمی‌شوند.

**حذف تکراری:** دو ورودی یکی‌اند فقط اگر hash متن برابر باشد (همان پیامک دو بار)، یا پیامک و نوتیفیکیشن با حساب + مبلغ + مانده + اختلاف زمان کمتر از ۲ دقیقه جور شوند. بدون مانده، ادغام فقط «پیشنهاد» است، نه خودکار؛ دو خرید واقعاً مشابه پشت سر هم هرگز حذف نمی‌شوند.

## باتری: نزدیک به صفر

| کار | چطور |
| --- | --- |
| گرفتن پیامک | فقط وقتی اندروید پیامک تحویل می‌دهد؛ < ۱ ثانیه |
| نوتیفیکیشن | فقط فهرست سفید؛ بقیه بلافاصله رد |
| پیامک جاافتاده | اسکن صندوق هنگام باز شدن اپ، یا روزی یک بار هنگام شارژ |
| بکاپ | فقط هنگام شارژ و بیکاری |
| آپدیت و قیمت‌ها | روزی یک بار، با قید شبکه، همراه کارهای دیگر سیستم |
| یادآورها | اگر اجازه زنگ دقیق (`SCHEDULE_EXACT_ALARM`) هست، دقیق؛ از اندروید ۱۴ برای نصب‌های جدید پیش‌فرض داده نمی‌شود، پس بدون آن یادآور عادی (`setWindow`) با کمی تأخیر + یک بار توضیح در تنظیمات. یادآوری هیچ‌وقت بی‌صدا از دست نمی‌رود |
| نمایش | تم مشکی مطلق، انیمیشن کوتاه، بدون انیمیشن همیشگی |

ممنوع: Foreground Service دائمی، WakeLock، polling، مکان‌یابی. درخواست خاموش کردن بهینه‌سازی باتری فقط وقتی که مقایسه با صندوق نشان دهد پیامکی جا افتاده (معمولاً شیائومی)، یک بار و با توضیح. هر نسخه قبل از انتشار یک شبانه‌روز با Battery Historian یا گزارش باتری گوشی بررسی شود.

## شبکه (تنها درخواست‌های مجاز، همه قابل خاموش کردن)

هیچ قابلیتی به سایت sarejam.ir وابسته نیست (فعلاً فقط دامنه خریداری شده). اپ بدون اینترنت کامل کار می‌کند.

1. **بررسی نسخه جدید:** `https://api.github.com/repos/arzmolaei/sarejam/releases/latest` (روزی حداکثر یک بار، قابل خاموش کردن). اگر مخزن بعداً خصوصی شد، یک مخزن عمومی جدا فقط برای فایل‌های نصبی (`sarejam-releases`) ساخته و آدرس در یک ثابت عوض می‌شود. اگر درخواست شکست خورد، اپ چیزی نشان نمی‌دهد.
2. **الگوهای جدید بانک (نسخه ۵):** `banks.json` در همان Releases. فقط با **امضای دیجیتال** معتبر (کلید عمومی داخل اپ) پذیرفته می‌شود و `version`، `schemaVersion`، `minAppVersion` دارد. قبل از اعمال، روی نمونه‌های داخلی اپ تست می‌شود؛ نسخه قبلی برای برگشت نگه داشته می‌شود و هیچ‌وقت تراکنش‌های دستی‌شده را عوض نمی‌کند.
3. قیمت طلا و ارز (نسخه ۴)

هیچ داده کاربر در هیچ درخواستی نیست.

## پایداری، آپدیت، بکاپ

- GitHub Actions: هر push → build + test؛ هر tag `v*` → APK امضاشده در Releases (همان جایی که بررسی آپدیت می‌خواند).
- کلید امضا: GitHub Secrets + یک نسخه آفلاین نزد صاحب پروژه. گم شدنش = هیچ کاربری نمی‌تواند آپدیت کند.
- نسخه‌گذاری `اصلی.فرعی.اصلاحی`، تغییرات فارسی در هر Release.
- تست روی شبیه‌ساز اندروید ۸، ۱۱، ۱۳ و آخرین نسخه.
- ثبت خطا روی گوشی؛ دکمه «گزارش مشکل» بدون داده مالی.
- بکاپ خودکار روزانه، رمزدار با رمز کاربر، پوشه دلخواه (SAF) یا گوگل‌درایو (فقط با انتخاب کاربر). نگهداری: ۷ روزانه + ۴ هفتگی + ۳ ماهانه، تا یک باگ جدید ظرف یک هفته همه بکاپ‌های سالم را پاک نکند. هر بکاپ checksum دارد و بعد از ساخت یک بار آزمایشی باز و شمرده می‌شود؛ خطا = هشدار. فایل `.sarejam` روی هر نسخه برابر یا جدیدتر بازگردانی می‌شود. قبل از هر Migration بکاپ خودکار.
- خروجی Excel/CSV، ورودی CSV، گزارش PDF.

## امنیت

دیتابیس SQLCipher با کلید Keystore · قفل اختیاری · `FLAG_SECURE` اختیاری · حالت مخفی · پیامک رمز هرگز ذخیره نمی‌شود · فقط اجازه `RECEIVE_SMS` و `READ_SMS`؛ هرگز `SEND_SMS` یا مخاطبین.
